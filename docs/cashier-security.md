# 个人收款码安全边界

## 本版本收紧

- 公共支付查询只在支付尝试为 CREATED/PROCESSING、业务订单为 CREATED/PENDING 且未到最早到期时间时返回二维码。账单支付缺少识别期限时拒绝展示。支付成功、失败、关闭、UNKNOWN 或业务订单已经结束时隐藏支付 payload，不改变数据库支付结果。
- 收银台每秒检查到期时间；过期立即停止展示二维码，不依赖 Worker 关单。状态查询失败时暂停展示，已有付款继续等待后续确认，不诱导重复付款。
- 备注模式必须有且只有一个完整正确的识别码；即使流水有商户单号，也不能替代备注要求。无备注时的金额查询只选择显式 AMOUNT 模式支付单，不再把 REMARK 模式订单纳入金额兜底。多识别码转差错处理，已有金额、有效期、多候选与交易号去重约束保留。
- 收银台和公共查询添加禁止缓存、禁止索引、禁止发送 Referer，以及禁止 iframe 嵌入的响应头。反向代理/CDN 不应覆盖这些策略；不要缓存公共支付查询。

## 不能承诺的保护

静态收款码可以被截图、保存和转发，隐藏页面不等于撤销支付宝收款能力。随机支付链接应视为持有者可访问的信息，不要公开发布。备注也不是付款人身份认证，知道备注的人仍可付款给该订单；且官方账务明细接口不下发备注，备注模式只对能抓到备注的外部 Watcher 有效，内置采集器应使用金额模式。金额模式无法区分同额日常转账，应隔离业务收款与日常转账。系统不会自动更改已有应用的匹配模式或迁移账号。

已经付款但到账延迟、备注不符、金额错误或有效期之外的流水需管理员核对；订单驱动采集的补查期以外晚到账可能不会被自动发现。个人账单渠道退款仍需人工处理。

升级保留原 .env 和 SECRETS_ENCRYPTION_KEY，重新构建 api/worker/web。本轮不新增数据库迁移。真实账号仍需验证缺备注、错备注、多备注、同额转账、到期页面和重复流水；本地测试不是资金安全审计。
