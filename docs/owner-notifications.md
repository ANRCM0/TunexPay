# 本人通知：邮箱与飞书

## 配置

升级后进入「支付渠道 → 本人通知 · 邮箱与飞书」。渠道默认关闭，配置写入数据库并加密，独立于业务 Webhook。

- 邮箱：SMTP 公网主机、465（TLS）或 587（强制 STARTTLS）、登录账号、密码/授权码、发件和收件邮箱。证书必须有效，禁止明文 SMTP、自签名证书和内网地址。主机解析结果校验后固定连接 IP，TLS 使用原主机名验证证书。供应商可能要求开启 SMTP 并生成授权码，不能一定使用普通登录密码。
- 飞书：在私密群添加自定义机器人，将 Webhook 填入面板。仅接受 `https://open.feishu.cn/open-apis/bot/v2/hook/...`。如果启用了机器人签名校验，填写对应密钥；按官方 timestamp+secret HMAC-SHA256 规则签名。机器人关键词安全策略可设置 `TUOXIN Pay`（所有通知标题包含该文本）。IP 白名单须包含服务器实际出口 IP。

飞书配置参考：[官方自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。这是群机器人通知，不是给个人账号发私聊消息。

敏感字段不回显，留空保留原值；明确勾选清除才删除。启用渠道的必需项不能清空，需要先关闭该渠道。保存采用 revision 防覆盖，冲突后重新加载。先保存再测试，测试按钮创建任务而不是宣称已成功，每渠道每分钟最多测试一次。下方最近 50 条记录中 SUCCESS 表示 SMTP 服务接受邮件或飞书返回成功，并不保证邮箱最终投递/手机已读。

## 提醒范围

- 业务订单收款成功：应用、订单号、支付单、金额、时间。
- 晚到重复支付、流水差错：提示登录后台核对，不发送原始流水、付款人、备注或密钥。
- 业务 Webhook 重试耗尽：提醒业务系统可能尚未完成充值，不对每一次暂时失败刷屏。
- 采集连续失败至少 3 次：每 15 分钟最多生成一次提醒。账号绑定冲突或 Worker 整体离线的外部监控不包含在本版，需要额外监控；Worker 停止时无法依赖自身发送告警。

未匹配但非差错的流水、每日摘要、恢复提醒和通知死信手动重发尚未包含。Mock 收款不发本人收款提醒，独立测试按钮可验证渠道。

## 可靠性与边界

Worker 从业务事务已提交的事件生成本人通知，通知 seen 标记和任务在同一事务提交，不改支付结果。没有按自增 ID 跳过历史游标，以避免事务提交次序导致漏事件；首次初始化之前的历史事件不补发。事件生成失败时下轮重扫未处理事件。

邮箱和飞书各有任务、去重键、租约和状态；发送失败最多自动尝试 5 次并退避，失败不影响另一个渠道或支付/业务回调。关闭渠道后未发送任务取消；事件开关影响后续生成，已生成的任务不因事件开关取消。保存后尚未投递的任务使用最新收件配置。发送与状态提交不能原子化，网络超时或崩溃恢复仍可能出现重复提醒；本人通知只供参考，不作为业务入账凭证。

状态：PENDING 待发送，PROCESSING 发送中，SUCCESS 服务接受，DEAD 重试耗尽，CANCELLED 渠道已关闭。错误记录只保存通用错误码，避免 SDK 异常泄露 Webhook 或 SMTP 凭证。

## 升级

保留原 .env、数据库和 `SECRETS_ENCRYPTION_KEY`，执行 `docker compose up -d --build api worker web`。API 启动应用 `202609160008_owner_notifications`。确保 `WEB_PUBLIC_URL` 为实际公网 HTTPS Origin，否则配置/测试请求拒绝。新依赖 nodemailer，Prisma Client 和 CLI 固定同一 6.12.0 版本。

本地测试不连接真实邮箱或机器人，不替代线上迁移验证。升级后分别测试两渠道并验证实际收件。上一轮安全审查发现的管理默认密钥、外部 Watcher、Mock 隔离、状态并发和业务 Webhook 内网防护问题尚未在本轮修复，正式充值前仍需处理。
